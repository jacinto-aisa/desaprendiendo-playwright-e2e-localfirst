Un curso para que los programadores junior no solo sepan pedir código a una IA, sino evaluar si están construyendo algo entendible, probado y preparado para cambiar.

JARDIN

No vamos a enseñar solo a hacer programas que funcionen. Vamos a enseñar a construir programas que puedan crecer, cambiar y seguir entendiéndose.

Por qué este curso ahora

la IA acelera; el criterio decide

La IA puede generar código muy deprisa, pero un junior necesita una brújula para saber si ese código resuelve el problema correcto, si está acoplado, si puede probarse y si soportará el siguiente cambio del cliente.

Arquitectura del curso

adaptable a 16, 24 o 40 horas
1. Problema y criterios de aceptaciónAntes de escribir código, el alumno aprende a justificar qué se quiere resolver.
2. Dominio y abstraccionesIdentificar entidades, valores, roles, comportamientos y detalles que todavía no importan.
3. Variabilidad y diseño para el cambioDetectar reglas cambiantes y elegir composición, interfaces, estrategias o validadores.
4. Contratos, SOLID y responsabilidadesReparto de piezas, límites claros y dependencias hacia abstracciones.
5. Pruebas como pensamientoLa primera prueba fija el comportamiento mínimo antes de complicar el diseño.
6. Refactorización seguraNombrar mejor, reducir duplicidad, desacoplar y dejar el código listo para el siguiente cambio.
Cómo se vive en clase

Del prompt al criterio técnico.

El alumno puede partir de una solución generada por IA o escrita a mano. Después se introduce un cambio realista y se revisa si el diseño aguanta.

Entregables para la empresa

  • Ficha de problema y criterios de aceptación.
  • Mapa de abstracciones y vocabulario del dominio.
  • Tabla de variabilidad y riesgos de cambio.
  • Contratos, responsabilidades e interfaces previstas.
  • Pruebas iniciales y checklist de refactorización.

Qué gana el programador junior

  • No precipitarse a codificar sin comprender.
  • Distinguir concepto de detalle accidental.
  • Detectar cuándo la IA propone una solución rígida.
  • Usar pruebas para pensar, no solo para verificar.
  • Perder miedo a mejorar código que ya funciona.
Mensaje para clientes JARDIN no vende “más prompts”: vende programadores capaces de razonar el software que la IA acelera.
